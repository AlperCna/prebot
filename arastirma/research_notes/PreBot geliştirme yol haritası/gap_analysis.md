## What did each report recommend?

### Takeaway
All four reports converge on the same core: an on-demand "availability pool + targeted wave call + first-accept + 15-min listing" with no Riot API in the MVP, strong KVKK/Riot-policy hygiene, and the explicit warning that **liquidity (simultaneous available fillers), not code, is the main risk**, so launch must be concentrated (seed 10–20 fillers, one partner community, announced "pre saatleri") and measured (fill rate, p50/p90 time-to-fill, no-show, opt-out). WEB moved the core channel to a PWA with Web Push; BEST/R2 supply most matching, trust and launch details; R1's weekly-roster idea is dead but its reputation/no-show principles survive.

### Inferences
- The research set is internally consistent on the core loop; the product already matches that loop. The unimplemented remainder clusters into five themes: (1) trust & safety (block, report, moderation, age bracket, reliability/no-show penalties, positive badge); (2) notification hygiene (snooze/mute, extend prompts, battery tip, install CTA, closing stale notifications); (3) ops (backups, rate limiting, observability, security headers, Dependabot); (4) measurement (no-show/show rate, p90, accept latency, push-ready ratio, repeat use, opt-out, event log); (5) launch/distribution (OG preview, pre saatleri, partner pilot, survey, Riot production application).

### Gaps
- `research_notes/**` were only skimmed via their Takeaways; minor recommendations buried in Cited Findings (e.g. Discord DM-specific rules, Components V2 caveats) may be missing from this list.
- Whether the concierge test, observation sheet or survey were done offline cannot be determined from the repo (no data files committed).

### Inferences
- Highest-leverage gaps before/at launch, in order: (1) backups + rate limiting + basic error alerting (cheap, prevents catastrophic loss/abuse); (2) no-show recording + `MetricEvent` log + p90/accept-latency/push-ready metrics (the research's success criterion cannot be measured otherwise, and "Gelmedi oranı" is already a README item); (3) OG preview + Web Share/WhatsApp share (the only ban-independent viral loop); (4) block/report/admin ban + age bracket (Terms promises account closure that doesn't exist; child-safety exposure); (5) KVKK text completion (Md. 9 transfer, push data, controller contact); (6) snooze/extend prompts and battery/install tips (retain permission, reduce opt-out).

- Passkeys, Riot verification, Spectator auto-close, voice channel and Discord DM fallback are lower priority until real usage data exists; the research itself says to add features only after thresholds are met.
