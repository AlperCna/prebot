# Technical best practices for production-hardening PreBot (.NET 10 Blazor PWA + Web Push), as of Nov 2026

Scope note: Research done 2026-11-09. Priority tags used in Inferences: **P0** = do now (cheap, high risk reduction), **P1** = next, **P2** = nice-to-have. Items marked "(unverified)" come from general knowledge or a non-authoritative page and should be checked before acting on them.

## 1. Web Push / PWA in 2026 (iOS, Android, permission UX, protocol hygiene, library choice)

### Takeaway
Web Push is usable on all of PreBot's target platforms. On iPhone it only works for Home Screen web apps. Safari 18.4+ (iOS/iPadOS 18.4, macOS 15.5) adds "Declarative Web Push", a JSON payload format the browser can render without a service worker. That format is backward compatible, so adopting it now for all platforms is cheap. The biggest operational wins are: delete subscriptions on 404/410, set TTL/Urgency/Topic deliberately, keep payloads well under 4 KB, and ask for permission only after a user gesture with a soft-ask first. Lib.Net.Http.WebPush is still maintained and remains the de-facto .NET choice.

### Cited Findings
**iOS / Safari / Declarative Web Push**
- Declarative Web Push is available on iOS and iPadOS 18.4 for web apps added to the Home Screen. It removes the need for a service worker to display notifications. — [WebKit: Features in Safari 18.4](https://webkit.org/blog/16574/digital-credentials-api/)
- On the Mac, Declarative Web Push needs Safari 18.5 (macOS 15.5). — [MacTech](https://www.mactech.com/2025/05/12/with-safari-18-5-included-in-macos-15-5-apple-added-declarative-web-push)
- Payload format: a top-level `"web_push": 8030` opts in to declarative parsing (a nod to RFC 8030). A `notification` object with a non-empty `title` is required. `navigate` (a URL opened on activation) is required. Optional fields include `body`, `lang`, `dir`, `silent`, and `app_badge` (updates the Badging API badge). — [WebKit: Meet Declarative Web Push](https://webkit.org/blog/16535/meet-declarative-web-push/)
- A service worker can still optionally change the notification. If that fails, the declarative message itself is used as a fallback. Older browsers handle the same JSON through the classic SW `push` handler, so sites can standardize on the declarative format and update their SW `push` handler to display it. — [WebKit: Meet Declarative Web Push](https://webkit.org/blog/16535/meet-declarative-web-push/)
- `window.pushManager.subscribe()` (with `userVisibleOnly: true` and `applicationServerKey`) works without a service worker in Safari. If a root-scoped SW exists, it shares the same subscription. Declarative messages always produce a visible notification, so silent-push penalties don't apply to them. — [WebKit: Meet Declarative Web Push](https://webkit.org/blog/16535/meet-declarative-web-push/)
- iOS 26 / iPadOS 26: websites added to the Home Screen now open as web apps by default. Users can turn "Open as Web App" off when adding. — [heise](https://heise.de/-10749652); [iDownloadBlog](https://www.idownloadblog.com/?p=1042117)
- EU: Apple planned to remove Home Screen web apps in the EU with iOS 17.4 (Feb 2024) under the DMA, then reversed the decision (Mar 2024). — [MacRumors (removal)](https://www.macrumors.com/2024/02/15/ios-17-4-web-apps-removed-apple/); [MacRumors (walk-back)](https://www.macrumors.com/2024/03/01/apple-walks-back-decision-to-disable-eu-web-apps/). Turkey is not in the EU/DMA scope, so this doesn't affect PreBot's users.
- (unverified, Apple doc fetch failed) Apple's web push docs say: permission must be requested from a user gesture; every push must show a visible notification or permission can be revoked; endpoints are on `web.push.apple.com`; Home Screen web apps can use `navigator.setAppBadge()` / `clearAppBadge()`. — [Apple Developer: Sending web push notifications](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers). Note that the fallback summary for this page gave `"web_push": 1`, which contradicts WebKit's own `8030`. **Use 8030 (WebKit primary source).**

**Protocol hygiene (all browsers)**
- `TTL` is required: the number of seconds the push service may hold a message. With `TTL: 0`, the service tries immediate delivery and drops the message if it can't. The push service may shorten the TTL. — [web.dev: Web Push Protocol](https://web.dev/articles/push-notifications-web-push-protocol)
- `Topic` lets a new message replace a pending one with the same topic while the device is offline. `Urgency` takes `very-low`, `low`, `normal` (the default) or `high`. — [web.dev](https://web.dev/articles/push-notifications-web-push-protocol)
- Push services must accept payloads of at least 4096 bytes. Larger payloads may get a 413. — [web.dev](https://web.dev/articles/push-notifications-web-push-protocol)
- What each response code means: 201 = accepted; 400 = bad headers; **404 = expired, delete the subscription**; **410 = gone, remove it from the server**; 413 = payload too large; 429 = rate limited, honor `Retry-After`. — [web.dev](https://web.dev/articles/push-notifications-web-push-protocol)

**Permission UX**
- Chrome moves sites with very low acceptance rates into the "quieter" permission UI automatically, and back out when acceptance improves. Sites that prompt as soon as the user arrives tend to have very low accept rates. Testing flag: `chrome://flags/#quiet-notification-prompts`. — [Bilogrevic et al., USENIX Security 2021 (Google)](https://www.usenix.org/conference/usenixsecurity21/presentation/bilogrevic); [WebEngage summary](https://webengage.com/blog/quiet-web-push-permission-prompt-chrome-firefox/)
- Soft-ask pattern: show your own in-page explainer first ("what you'll get, when, why"). Only users who say yes see the native prompt. Never prompt on page load. — [OneSignal](https://onesignal.com/blog/boost-your-web-push-opt-in-rates/); [Pushwoosh](https://help.pushwoosh.com/hc/en-us/articles/30915881157021-What-is-the-recommended-way-to-ask-users-to-subscribe-to-web-push-notifications) (vendor sources)

**Service worker update strategy**
- By default, a new SW waits until every client is closed. `skipWaiting()` on its own doesn't take control of open tabs (`clients.claim()` does that). Forcing both can leave new SW code serving pages whose HTML references old assets. Workbox recommends a "new version available → reload" prompt mainly when you precache heavily. — [Chrome Developers: Handling service worker updates](https://developer.chrome.com/docs/workbox/handling-service-worker-updates)
- Common pattern: show a banner, post a `SKIP_WAITING` message to the waiting worker when the user accepts, and reload on `controllerchange`. Don't delete old caches while old-version pages may still be open. — [Chrome Developers](https://developer.chrome.com/docs/workbox/handling-service-worker-updates); [frontcore notes](https://frontcore.vercel.app/docs/frontend/caching-and-storage/service-worker-lifecycle-traps) (secondary)

**Library**
- Lib.Net.Http.WebPush (tpeczek, MIT) is still maintained. Recent releases: 3.2.1 (key casing/validation fix), 3.3.0 (Mozilla Autopush return codes), 3.3.1 (empty-content fix, released alongside Lib.AspNetCore.WebPush 2.2.2). Only one open issue. — [GitHub releases](https://github.com/tpeczek/Lib.Net.Http.WebPush/releases)
- The only other .NET option found is WebPush.Alt, a port of web-push-libs with very low downloads and a single maintainer. — [NuGet WebPush.Alt](https://packages.nuget.org/packages/WebPush.Alt)

### Inferences
- **P0 — Subscription cleanup:** catch `PushServiceClientException` (or check the status code) from Lib.Net.Http.WebPush. On 404/410, delete the row. On 429, back off using `Retry-After`. On 413, log an alert. Also add a `LastSuccessAt`/`FailureCount` column so subscriptions that keep failing get pruned. This also serves KVKK data minimization.
- **P0 — Headers per message type:** for "listing filled / your match is ready", use `Urgency: high`, a short TTL (e.g., 5–15 min, since a LoL lobby notice is worthless later) and `Topic = listing-{id}`, so repeated updates collapse into one. For informational announcements, use `Urgency: normal/low` and a longer TTL. Lib.Net.Http.WebPush's `PushMessage` exposes `TimeToLive`, `Urgency` and `Topic` (verify property names in the README; not confirmed by the releases page).
- **P0 — Soft-ask:** show an in-app card ("Get notified when your lobby fills?"). Call `Notification.requestPermission()` only from that button's click handler, and only after the user's first meaningful action (e.g., after creating or joining their first listing). This matters on iOS (gesture required) and protects against Chrome's quiet-UI demotion.
- **P1 — iOS onboarding:** detect iOS Safari when the page isn't standalone (`navigator.standalone` / `display-mode: standalone` media query) and show "Share → Add to Home Screen" instructions *before* offering push. Push isn't possible in an iOS Safari tab.
- **P1 — Declarative payload everywhere:** send `{"web_push":8030,"notification":{"title":…,"body":…,"navigate":"https://…/listing/123","app_badge":N}}` and teach `sw.js`'s `push` handler to parse that shape. Then iOS 18.4+ renders it natively and Chrome/Edge/Firefox use the SW. Keep the payload well under 4 KB: IDs and short strings, no full listing objects.
- **P1 — `notificationclick`:** in the SW, call `event.notification.close()`. Then call `clients.matchAll({type:'window', includeUncontrolled:true})`, focus an existing PreBot window and `navigate()` it to the target URL if one is found, otherwise call `clients.openWindow(url)`. Wrap the whole thing in `event.waitUntil`. Use `actions` buttons (e.g., "Open lobby", "Dismiss") only as progressive enhancement: iOS doesn't show action buttons in all contexts (not verified in this research).
- **P1 — Badging:** use `navigator.setAppBadge(count)` where supported (installed PWAs on Windows/Android Chrome, iOS Home Screen apps) and `app_badge` in declarative payloads.
- **P2 — SW update:** PreBot is Interactive Server, so the SW probably caches little. Prefer a simple "new version → Reload" toast over `skipWaiting()` + `clients.claim()`, and version `sw.js` on each deploy.
- Keep Lib.Net.Http.WebPush. There is no better-maintained .NET alternative.

### Gaps
- Couldn't fetch Apple's primary web push documentation. The iOS-specific limits (gesture requirement, revocation policy, notification `actions` support on iOS, exact header support) are from general knowledge.
- Didn't verify whether Lib.Net.Http.WebPush 3.3.x targets .NET 10 explicitly, or whether it has helpers for declarative payloads (the payload is just JSON content, so none should be needed).
- No primary Google page on 2026 Android Chrome behavior (e.g., notification permission auto-revocation for low-engagement sites) was retrieved.
- PWA install-prompt (`beforeinstallprompt`) status in 2026 wasn't researched.

## 2. Blazor Server (Interactive Server) production practices in .NET 10

### Takeaway
.NET 10 adds three things relevant to PreBot's mobile-heavy users: a CSP-friendly `ReconnectModal` component, circuit state persistence (on by default: 1,000 circuits kept for 2 hours in memory) and the `Blazor.pauseCircuit()`/`resumeCircuit()` JS APIs. Mark important in-progress form state with `[PersistentState]`. Budget about 250–300 KB of RAM per circuit. Configure forwarded headers for Caddy. Sticky sessions aren't relevant on a single node.

### Cited Findings
- The .NET 10 template ships a `ReconnectModal` component with collocated CSS/JS. It doesn't inject styles programmatically, so it works with a strict `style-src` CSP. It dispatches a `components-reconnect-state-changed` event and adds a `retrying` state. — [What's new in ASP.NET Core 10](https://learn.microsoft.com/en-us/aspnet/core/release-notes/aspnetcore-10.0)
- Circuit state persistence covers tab throttling, mobile app switching, network interruptions, proactive pausing and enhanced navigation, as long as no full page refresh happens. It's enabled by default with `AddInteractiveServerComponents()`. The default store is MemoryCache: up to 1,000 persisted circuits for 2 hours, set via `CircuitOptions.PersistedCircuitInMemoryMaxRetained` and `PersistedCircuitInMemoryRetentionPeriod`. — [MS Learn: Blazor server-side state management](https://learn.microsoft.com/en-us/aspnet/core/blazor/state-management/server?view=aspnetcore-10.0)
- Only state marked `[PersistentState]` (public component properties, or scoped services registered with `RegisterPersistentService<T>()`) is persisted. It must be JSON-serializable: cyclic references and ORM entities may fail. Use `@key` in loops. Recovery isn't guaranteed. — [MS Learn](https://learn.microsoft.com/en-us/aspnet/core/blazor/state-management/server?view=aspnetcore-10.0)
- `Blazor.pauseCircuit()` / `Blazor.resumeCircuit()` can be called from JS, e.g., on `visibilitychange`, to evict hidden-tab circuits and free server memory. — [MS Learn](https://learn.microsoft.com/en-us/aspnet/core/blazor/state-management/server?view=aspnetcore-10.0)
- .NET 11+ (not .NET 10) adds an opt-in `Microsoft.AspNetCore.Components.Server.AutoPause` package and server-triggered `Circuit.RequestCircuitPauseAsync` for graceful pause during deploys. On mobile, the OS suspends JS within seconds on Android and up to about 30 s on iOS, so graceful pause on backgrounding isn't guaranteed. — [MS Learn](https://learn.microsoft.com/en-us/aspnet/core/blazor/state-management/server?view=aspnetcore-10.0) (flag: **.NET 11 feature**, not available on .NET 10)
- About 250 KB per circuit for a minimal app. Planning baseline: 5,000 concurrent users ≈ 1.3 GB (≈273 KB/user). Target UI latency ≤ 250 ms. WebSockets are strongly preferred; Long Polling is the fallback and logs a console warning. — [MS Learn: Host and deploy server-side Blazor](https://learn.microsoft.com/en-us/aspnet/core/blazor/host-and-deploy/server/?view=aspnetcore-10.0)
- Other .NET 10 changes: `NavigationManager.NotFound()`, `Router.NotFoundPage` and `UseStatusCodePagesWithReExecute` replace `<NotFound>`. `blazor.web.js` is served as a fingerprinted, compressed static asset. Blazor emits metrics and traces for circuits, navigation and event handling. Cookie auth now returns 401/403 instead of redirecting for API/SignalR endpoints (`IApiEndpointMetadata`). Kestrel's memory pool releases idle blocks. — [What's new in ASP.NET Core 10](https://learn.microsoft.com/en-us/aspnet/core/release-notes/aspnetcore-10.0)
- Forwarded headers: the middleware is off by default (`ForwardedHeaders.None`). Enable `XForwardedFor | XForwardedProto` and call `UseForwardedHeaders()` before `UseHsts` and other middleware. By default only loopback proxies are trusted, so requests from a Caddy container on a Docker network are ignored until you add its IP/subnet to `KnownProxies`/`KnownNetworks`. `ASPNETCORE_FORWARDEDHEADERS_ENABLED=true` trusts all forwarders and doesn't restrict by `KnownProxies`. The default `ForwardLimit` is 1. — [MS Learn: Proxy & load balancer](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer?view=aspnetcore-10.0)
- Caddy's `reverse_proxy` handles WebSocket upgrades automatically. — [DEV: Caddy hardening](https://dev.to/jonesrussell/caddy-hardening-security-headers-and-rate-limiting-19go) (secondary)
- A .NET 10 RC2 GitHub issue reported the default template's reconnection panel never reconnecting. Not confirmed whether it's fixed in GA. — [dotnet/aspnetcore#64228](https://github.com/dotnet/aspnetcore/issues/64228)

### Inferences
- **P0 — Forwarded headers done right:** with Caddy and the app on a Docker bridge network, set `KnownNetworks` to the compose network's subnet (or a fixed Caddy container IP) rather than using `ASPNETCORE_FORWARDEDHEADERS_ENABLED`. Otherwise `RemoteIpAddress` is Caddy's IP, and per-IP rate limiting and logging are useless. Verify by logging `RemoteIpAddress` once.
- **P0 — `[PersistentState]`** on the "create listing" form model, filter selections and Riot ID inputs, so Android/iOS app-switching doesn't wipe a half-filled form.
- **P1 — Use the template's `ReconnectModal`** (copy it from a fresh `dotnet new blazor` if the app predates .NET 10) and localize it to Turkish ("Bağlantı koptu, yeniden bağlanılıyor…").
- **P1 — Hidden-tab pause:** call `Blazor.pauseCircuit()` on `visibilitychange` → hidden (perhaps after a 30–60 s delay on desktop) to save VPS RAM. Test carefully, because circuits that push live listing updates would stop receiving them. Alternatively, only pause after N minutes hidden.
- **P1 — Static SSR for read-mostly pages:** landing, statistics page, privacy/KVKK pages and listing directory can be static SSR with enhanced navigation (no circuit, cacheable, crawlable). Keep Interactive Server only where live updates or rich interaction are needed (listing detail, create/join). WebAssembly isn't worth it at this scale.
- **P2 — Capacity:** on a ~6 € VPS with ~2–4 GB RAM, a few hundred concurrent circuits are trivially affordable. Memory is unlikely to be the first bottleneck. Watch the SQLite write lock and the bot instead.

### Gaps
- Whether `ForwardedHeadersOptions.KnownNetworks` is obsoleted in favor of `KnownIPNetworks` (`System.Net.IPNetwork`) in .NET 10 wasn't confirmed. The .NET 10 doc page still shows `KnownNetworks`. Check for an obsoletion warning at compile time.
- SignalR `HubOptions` limits (`MaximumReceiveMessageSize`, default 32 KB) and `CircuitOptions` defaults (`DisconnectedCircuitRetentionPeriod` 3 min, `DisconnectedCircuitMaxRetained` 100) are from general knowledge, not re-verified here.

## 3. Security (rate limiting, CSP/headers, cookies, OAuth, passkeys, secrets, dependency scanning, abuse)

### Takeaway
Use the built-in `Microsoft.AspNetCore.RateLimiting` middleware, partitioned by user ID for authenticated actions and by real client IP otherwise. But HTTP-level limits don't see Blazor Interactive Server button clicks, which travel over the already-open SignalR connection, so listing create/join needs an app-level check too. Ship a CSP (start Report-Only), HSTS and the usual headers from Caddy or the app. Passkeys in .NET 10 are an ASP.NET Core Identity feature, which PreBot (cookie auth + external OAuth only) doesn't use, so they're optional and low priority.

### Cited Findings
- Rate limiting middleware: fixed window, sliding window, token bucket and concurrency limiters, plus `PartitionedRateLimiter` keyed by user name or `RemoteIpAddress`, `RejectionStatusCode`/`OnRejected` with `Retry-After`, and chaining via `CreateChained`. Counters are in-memory per instance. — [MS Learn: Rate limiting](https://learn.microsoft.com/en-us/aspnet/core/performance/rate-limit?view=aspnetcore-10.0)
- For Blazor: `app.MapRazorComponents<App>().AddInteractiveServerRenderMode().RequireRateLimiting("policy")`, or `@attribute [EnableRateLimiting("x")]` per routable component or `_Imports.razor`. `UseRateLimiter` must come after `UseRouting` for endpoint policies. `UseStatusCodePagesWithReExecute` must come before both. — [MS Learn: Rate limiting](https://learn.microsoft.com/en-us/aspnet/core/performance/rate-limit?view=aspnetcore-10.0)
- Warning: partitioning on user-controlled input (e.g., spoofable IPs) creates DoS risk, because each key creates a cached limiter. — [MS Learn: Rate limiting](https://learn.microsoft.com/en-us/aspnet/core/performance/rate-limit?view=aspnetcore-10.0)
- Rate-limiter metrics are emitted under `Microsoft.AspNetCore.RateLimiting`. — [MS Learn: Rate limiting](https://learn.microsoft.com/en-us/aspnet/core/performance/rate-limit?view=aspnetcore-10.0)
- Blazor CSP (.NET 10 sample for Blazor Web Apps): `base-uri 'self'; default-src 'self'; img-src data: https:; object-src 'none'; script-src 'self' 'wasm-unsafe-eval' 'unsafe-hashes' 'sha256-qnHnQs7NjQNHHNYv/I9cW+I62HzDJjbnyS/OFzqlix0='; style-src https:; connect-src 'self' http: ws: wss:; upgrade-insecure-requests`. The hash covers the template NavMenu's inline `onclick`. Alternatively, move that handler to a JS file. The `ImportMap` inline script needs an SRI hash or nonce. — [MS Learn: Blazor CSP](https://learn.microsoft.com/en-us/aspnet/core/blazor/security/content-security-policy?view=aspnetcore-10.0)
- `frame-ancestors`, `report-to` and `report-uri` can't be set via `<meta>`; they need a header. Blazor Web Apps already send `frame-ancestors 'self'`, which can be tightened with `.AddInteractiveServerRenderMode(o => o.ContentSecurityFrameAncestorsPolicy = "'none'")`. Test with `Content-Security-Policy-Report-Only`. In .NET 10, `Virtualize` emits inline styles that break strict CSP (fixed in .NET 11). — [MS Learn: Blazor CSP](https://learn.microsoft.com/en-us/aspnet/core/blazor/security/content-security-policy?view=aspnetcore-10.0)
- Caddy: set HSTS and other headers in a reusable snippet imported per site, and remove `Server`. If the upstream app also sends a CSP, use `header_down -Content-Security-Policy` to avoid duplicates. — [DEV: Caddy hardening](https://dev.to/jonesrussell/caddy-hardening-security-headers-and-rate-limiting-19go); [Caddy community](https://caddy.community/t/why-is-content-security-policy-ignored/15937) (secondary)
- Passkeys: .NET 10 ASP.NET Core Identity supports WebAuthn/FIDO2 passkeys, and the Blazor Web App + Identity template includes passkey registration/login UI. The template still asks for a password first (a template choice). — [What's new in ASP.NET Core 10](https://learn.microsoft.com/en-us/aspnet/core/release-notes/aspnetcore-10.0); [MS Learn: Passkeys in Blazor](https://learn.microsoft.com/en-us/aspnet/core/security/authentication/passkeys/blazor); [Duende blog](https://duendesoftware.com/blog/20251007-passkeys-in-dotnet-10-blazor-apps-with-aspnet-identity)
- .NET 10 adds auth/authz metrics (challenges, forbids, sign-ins) and an Identity meter. — [What's new in ASP.NET Core 10](https://learn.microsoft.com/en-us/aspnet/core/release-notes/aspnetcore-10.0)

### Inferences
- **P0 — Two-layer rate limiting.** (a) HTTP layer: a global per-IP limiter (after correct forwarded headers) on `/signin-*`, `/api/push/subscribe` and any minimal-API endpoints, plus a modest global limit on `MapRazorComponents` (it only throttles page loads and circuit starts). (b) App layer: Interactive Server event handlers don't create new HTTP requests, so enforce domain rules in the service that creates or joins listings. For example, a user can have at most N open listings, create at most X listings per 10 min and join/leave at most Y times per minute. Use an in-memory `PartitionedRateLimiter<string>` keyed by user ID and call `AttemptAcquire(userId)` directly in the service. Return a friendly Turkish error. (Inference: SignalR hub messages bypass HTTP rate-limiting middleware; not stated explicitly in the docs retrieved.)
- **P0 — Security headers in Caddy** (single place): `Strict-Transport-Security "max-age=31536000; includeSubDomains"` (skip `preload` until sure), `X-Content-Type-Options nosniff`, `Referrer-Policy strict-origin-when-cross-origin`, `Permissions-Policy` (camera=(), microphone=(), geolocation=()), `-Server`. Put the CSP in the app (`App.razor` meta, or middleware), because the ImportMap hash/nonce is per request. Start with `Content-Security-Policy-Report-Only`.
- **P0 — Cookies:** auth cookie `HttpOnly`, `Secure` (`CookieSecurePolicy.Always`), `SameSite=Lax` (needed for the OAuth redirect back), a sensible `ExpireTimeSpan` with sliding expiration, and `__Host-` prefix if possible. Persist Data Protection keys to the Docker volume (`PersistKeysToFileSystem`), or every container redeploy logs everyone out and invalidates antiforgery tokens. (Inference: standard ASP.NET Core guidance, not fetched here.)
- **P0 — Secrets:** the VAPID private key, OAuth client secrets and Discord bot token should come from environment variables or Docker secrets, never from the repo. Since the repo is open source, add `gitleaks`/GitHub secret scanning with push protection. The VAPID JSON on a volume is fine if it's `chmod 600` and included in backups. Losing it invalidates all subscriptions.
- **P1 — Dependency scanning:** enable Dependabot for `nuget`, `docker` and `github-actions` ecosystems. Add a CI step `dotnet list package --vulnerable --include-transitive` that fails on high/critical findings (or `NuGetAudit` with `<NuGetAuditMode>all</NuGetAuditMode>`, `<WarningsAsErrors>NU1903;NU1904</WarningsAsErrors>`). Add a Trivy/Grype scan of the built image.
- **P1 — Abuse prevention:** sign-up is OAuth-only (Google/Discord), which already raises the cost of bot accounts. Add per-account action quotas, an admin "ban/shadow-ban user" flag, and optionally a minimum Discord account age check via the Discord API. A CAPTCHA (e.g., Cloudflare Turnstile) is likely unnecessary at this scale and adds a KVKK cross-border processor.
- **P2 — Passkeys:** skip. They require migrating to ASP.NET Core Identity, and users already authenticate via Google/Discord (which themselves support passkeys).
- **P2 — OWASP ASVS L1 self-check:** use the ASVS Level 1 checklist as a one-off review (authz on every listing mutation, IDOR checks on listing IDs, output encoding, logging of auth events).

### Gaps
- OWASP ASVS 5.0 specifics, OWASP Secure Headers recommended values and the official Caddy `header` directive docs weren't fetched. Header values above are standard practice and should be validated with securityheaders.com / Mozilla Observatory after deploying.
- Not confirmed whether the antiforgery middleware needs changes for PreBot's forms (Blazor SSR forms include `<AntiforgeryToken />` by default).

## 4. Observability on a single small VPS

### Takeaway
Instrument with OpenTelemetry in the app (built-in ASP.NET Core, Blazor, SignalR, rate-limiting, auth and EF Core meters/activities). For a zero-budget, single-VPS backend, the lightest practical combo is: **Seq (free Individual license) for structured logs/traces**, **GlitchTip or Sentry's free cloud tier for exceptions**, plus **an external uptime monitor** with `/health` endpoints. Full Grafana LGTM or SigNoz stacks are heavy for a ~6 € box.

### Cited Findings
- Seq's Individual license is $0/year: 1 user, community support, 50 GB storage limit, unlimited retention, alerts, integrations and SSO. Only one person may access the instance. Data is never sent to Datalust. — [Datalust pricing](https://datalust.co/Pricing)
- GlitchTip accepts official Sentry SDKs (including .NET) by pointing them at a GlitchTip DSN. It runs on about 4 containers (vs ~40 for Sentry self-hosted); one source says 256 MB minimum all-in-one, another a 512 MB template. Sentry self-hosted needs about 16 GB RAM plus swap. GlitchTip 6 was released Feb 2026. GlitchTip is MIT; Sentry self-hosted is BSL. — [DEV: GlitchTip vs Sentry](https://dev.to/selfhostingsh/glitchtip-vs-sentry-206o); [Railway template](https://railway.com/deploy/glitchtip-sentry-alternative); [SSOJet](https://ssojet.com/blog/best-sentry-alternatives-error-tracking) (secondary/vendor sources)
- SigNoz self-hosted runs several services (SigNoz, ClickHouse, OTel collector), and its resource needs are described as a deterrent for the smallest projects. Grafana LGTM is described as ~5 separate tools. Uptrace (single binary) and OpenObserve (~512 MB idle) are positioned as lighter. — [Virtua.cloud](https://www.virtua.cloud/learn/en/tutorials/self-host-signoz-openobserve-vps); [youngju.dev 2026 comparison](https://www.youngju.dev/blog/culture/2026-05-14-modern-monitoring-oss-2026-signoz-coroot-openobserve-sentry-self-hosted-uptrace-deep-dive.en) (secondary)
- .NET 10 emits Blazor metrics/tracing (component lifecycle, navigation, event handling, circuits), auth/authz metrics, Identity metrics and `Microsoft.AspNetCore.MemoryPool` metrics. `IExceptionHandler`-handled exceptions are no longer logged by default. — [What's new in ASP.NET Core 10](https://learn.microsoft.com/en-us/aspnet/core/release-notes/aspnetcore-10.0)

### Inferences
- **P0 — Health checks:** `builder.Services.AddHealthChecks().AddDbContextCheck<AppDb>()` plus a custom check for the Discord gateway connection state. Map `/health/live` (process up) and `/health/ready` (DB + bot). Wire the Docker `HEALTHCHECK` (chiseled images have no curl, so use a tiny `--healthcheck` CLI arg in the app or rely on compose's external probe) and an external monitor. **Uptime Kuma** self-hosted on the same VPS can't tell you when the VPS itself is down, so pair it with a free external monitor (Healthchecks.io for cron/backup heartbeats, UptimeRobot/Better Stack free tier for HTTP). (Inference; free-tier limits not verified here.)
- **P0 — Structured logging:** switch console logs to JSON (`builder.Logging.AddJsonConsole()`), or Serilog with a compact JSON formatter, so `docker logs` stays greppable and log shippers work. Cap Docker log size (`logging: driver: json-file, options: max-size: 10m, max-file: 5`) so logs don't fill the disk.
- **P1 — OpenTelemetry:** `AddOpenTelemetry().WithMetrics(m => m.AddAspNetCoreInstrumentation().AddRuntimeInstrumentation().AddMeter("Microsoft.AspNetCore.Components*","Microsoft.AspNetCore.RateLimiting","PreBot")).WithTracing(t => t.AddAspNetCoreInstrumentation().AddHttpClientInstrumentation().AddEntityFrameworkCoreInstrumentation())`, then `.UseOtlpExporter()` pointed at Seq (Seq ingests OTLP logs and traces). Add custom counters: listings created/filled, pushes sent/failed by status code, bot reconnects.
- **P1 — Errors:** add the Sentry .NET SDK pointed at Sentry's free SaaS tier or a self-hosted GlitchTip DSN. Scrub PII (`SendDefaultPii = false`), which KVKK requires; using Sentry SaaS also means a cross-border transfer (see section 7).
- **P2 — Metrics dashboards:** only consider Prometheus + Grafana if specific charts are needed. For a hobby app, Seq dashboards and `dotnet-counters` on demand are enough.

## 5. Data: SQLite in production (backups, WAL, migrations, retention, when to move to PostgreSQL)

### Takeaway
SQLite (WAL) is fine for PreBot's scale. The urgent gap is automated off-site backups. The two options: (a) **Litestream 0.5.x** for continuous replication to S3-compatible storage (use ≥0.5.2; 0.5 changed format and early 0.5.0 had bugs), or (b) a nightly `sqlite3 .backup` / `VACUUM INTO` snapshot plus off-site copy (rclone) plus a heartbeat ping. Never copy the raw `.db` file while the app runs, because committed data may sit only in the `-wal` file.

### Cited Findings
- Litestream 0.5 (Oct 2025) replaced the WAL-segment approach with the LTX format: transaction-aware backups, hierarchical compaction, faster restores. It dropped "generations" and added NATS JetStream replicas. **0.5 can't restore backups made by earlier versions.** — [Fly.io: Litestream v0.5.0](https://fly.io/blog/litestream-v050-is-here/); [Simon Willison](https://simonwillison.net/2025/Oct/3/litestream)
- Michael Lynch advised holding off on 0.5.0. 0.5.1 fixed most of the issues he hit and 0.5.2 the rest. Later releases go up to v0.5.7 (experimental read-only VFS for replicas). — [mtlynch.io](https://mtlynch.io/notes/hold-off-on-litestream-0.5.0); [newreleases v0.5.7](https://newreleases.io/project/github/benbjohnson/litestream/release/v0.5.7)
- In WAL mode, committed transactions can exist only in the WAL until a checkpoint, so copying just the `.db` is unsafe. The online backup API (`.backup`) or `VACUUM INTO` gives a coherent live snapshot. `.backup` is a byte-faithful copy (including free pages); `VACUUM INTO` writes a compacted copy but rewrites every page. — [OneUptime: Back up WAL-mode SQLite safely](https://oneuptime.com/blog/post/2026-09-08-back-up-wal-mode-sqlite-safely/view) (secondary)
- The output of `VACUUM INTO` uses rollback-journal (DELETE) mode regardless of the source; re-enable WAL after restoring if needed. — [Turso docs: VACUUM](https://docs.turso.tech/sql-reference/statements/vacuum)
- Vaultwarden's Docker images (a comparable SQLite-in-Docker app) don't include `sqlite3` or `cron`, so its wiki recommends running the backup cron on the host. — [Vaultwarden wiki](https://gitea.it/vaultwarden/vaultwarden-alternativa-bitwarden/wiki/commit/913a33d6b616e4baa0a43684a202684b0888cbcf)
- Untested backups are unproven; restore them periodically and run queries against the copy. — [OneUptime: Back up SQLite on Ubuntu](https://oneuptime.com/blog/post/2026-03-02-how-to-back-up-sqlite-databases-on-ubuntu/view) (secondary)

### Inferences
- **P0 — Backups:** simplest zero-cost path: a host cron (or a `BackgroundService` in the app running `VACUUM INTO '/backups/prebot-{date}.db'` via EF `ExecuteSqlRawAsync`, which avoids needing sqlite3 in a chiseled image) at 04:00 Turkey time. Then `rclone` to a free/cheap off-site target (Backblaze B2 / Cloudflare R2 free tier, or a second cheap box), keep 7 daily, 4 weekly and 6 monthly copies, and ping Healthchecks.io on success. Include the VAPID key file and the Data Protection keys directory in the same backup. Quarterly, do a restore test with `PRAGMA integrity_check`.
- **P1 — Litestream as a sidecar** container sharing the volume (continuous, RPO ~seconds) if the data becomes more valuable. Use ≥0.5.2. Encrypt replicas or use a bucket in a KVKK-acceptable location.
- **P1 — WAL hygiene:** keep `PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000` and `foreign_keys=ON` on every connection. Only one app process writes, which is fine. The default auto-checkpoint (1000 pages) is fine. Consider `PRAGMA wal_checkpoint(TRUNCATE)` before nightly backups. Litestream manages checkpoints itself, so don't mix manual truncation with it.
- **P1 — EF Core migrations in production:** stop calling `Database.Migrate()` at startup for anything risky. Generate idempotent SQL (`dotnet ef migrations script --idempotent`) or a migration bundle (`dotnet ef migrations bundle`) in CI. Take a backup immediately before applying. SQLite's limited `ALTER TABLE` means EF rebuilds tables, so test migrations against a copy of production data. (Inference: standard EF guidance, not fetched.)
- **P1 — Retention/cleanup job:** a daily `BackgroundService`/`PeriodicTimer` that hard-deletes closed listings older than N days (or anonymizes them for statistics), push subscriptions failing for >30 days, and orphaned sessions. Document the periods in the KVKK disclosure (section 7).
- **P2 — When to move to PostgreSQL:** when you need multiple app instances, sustained concurrent writes beyond what a single writer handles (e.g., lock-contention errors), full-text search or analytics beyond SQLite's capabilities, or managed PITR. None apply at the current scale.

### Gaps
- Official sqlite.org backup API / WAL docs weren't fetched (relied on secondary tutorials that agree with each other).
- Didn't verify Litestream's latest version as of Nov 2026 beyond v0.5.7.
- No benchmark data for SQLite write concurrency in EF Core 10.

## 6. Deployment on a single VPS (GHCR, updates, container hardening, Caddy)

### Takeaway
Build and push images to GHCR from GitHub Actions, then deploy via SSH (`docker compose pull && docker compose up -d`), with health-gated rollback. **Don't adopt Watchtower:** the containrrr repo was archived on 17 Dec 2025. Use .NET 10's Ubuntu Noble **chiseled** images (non-root by default, no shell or package manager), with `-extra` if ICU/time zones are needed. Turkish culture formatting and `Europe/Istanbul` probably require ICU.

### Cited Findings
- containrrr/watchtower was archived on 17 Dec 2025 and is read-only; the last release is v1.7.1. Community forks exist (nicholas-fedor/watchtower, openserbia/watchtower). — [Linuxiac](https://linuxiac.com/docker-update-tool-watchtower-reaches-end-of-maintenance/); [GitHub releases](https://github.com/containrrr/watchtower/releases); [openserbia fork](https://openserbia.github.io/watchtower/why-fork/)
- .NET 10 container images default to Ubuntu 24.04 (Noble); Debian images are no longer shipped. Images run as the non-root `app` user by default. Chiseled images have no shell or package manager. `mcr.microsoft.com/dotnet/aspnet:10.0-noble-chiseled-extra` adds ICU/tzdata for globalization. With SDK container publish, `<ContainerFamily>noble-chiseled-extra</ContainerFamily>` selects it. — [codewithmukesh](https://codewithmukesh.com/blog/containerize-dotnet-without-dockerfile/); [MS Learn: container images](https://learn.microsoft.com/ro-ro/dotnet/core/docker/container-images) (partly secondary; verify tags on MCR)
- A dotnet-docker issue reported the non-chiseled Noble image lagging on a GnuTLS security fix that the chiseled-extra image already had. — [dotnet/dotnet-docker#6860](https://github.com/dotnet/dotnet-docker/issues/6860)
- Caddy's `reverse_proxy` proxies WebSockets without extra config. Security headers are best put in a reusable snippet. — [DEV: Caddy hardening](https://dev.to/jonesrussell/caddy-hardening-security-headers-and-rate-limiting-19go) (secondary)

### Inferences
- **P0 — Image pipeline:** GitHub Actions builds on push to `master` and tags `ghcr.io/<owner>/prebot:{sha}` plus `:latest`. Then a deploy job SSHes in (a dedicated deploy user with only docker rights; key stored in GitHub Environments with required reviewers) and runs `docker compose pull && docker compose up -d --wait` (`--wait` honors healthchecks). If the health check fails, re-tag to the previous SHA. Pin images by SHA in `.env` so rollback is a one-line change.
- **P0 — Container hardening in compose:** `read_only: true` plus `tmpfs: /tmp`, a writable volume only for `/data` (SQLite, VAPID, DataProtection keys), `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, `user: app` (default) and memory limits (`mem_limit`). Make sure volume ownership matches the `app` UID (1654 in .NET 8+ images; verify).
- **P0 — Globalization:** a Turkish-locale app (dates, `ToUpper` on "i"/"İ", time zones) should use `noble-chiseled-extra`, or set `InvariantGlobalization=false` with ICU present. Otherwise Turkish casing and `Europe/Istanbul` lookups break silently.
- **P1 — Graceful shutdown:** set `HostOptions.ShutdownTimeout` (~30 s) so the Discord bot disconnects cleanly and in-flight push sends finish. Compose's `stop_grace_period: 30s` should match. A single node can't be truly zero-downtime with circuits; on .NET 10, rely on the reconnection UI and circuit persistence. Persistence is in-memory, so it's lost on restart unless HybridCache is backed by a persistent store. Deploy in low-traffic hours.
- **P1 — Caddy:** pin the Caddy image version, persist `/data` (certificates) and `/config` volumes, enable `encode zstd gzip`, use the security-headers snippet and add `log { format json }` with rotation. Caddy obtains and renews certificates automatically.
- **P1 — Host hardening:** SSH key-only login, `ufw` (allow 22/80/443 only), unattended-upgrades and fail2ban or CrowdSec. Don't expose the app or Seq ports publicly; bind them to `127.0.0.1` or the internal Docker network.
- **P2 — Automatic base-image updates:** a Dependabot `docker` ecosystem entry (or Renovate) opens PRs when `aspnet:10.0-*` digests change. That replaces Watchtower with a reviewable, CI-tested flow.

### Gaps
- Official Microsoft doc for chiseled image sizes and the default `app` UID wasn't fetched directly. Size estimates conflict (~120 vs ~130 MB).
- Official Caddy docs weren't fetched. The Caddy guidance comes from community sources.

## 7. KVKK compliance for a small Turkish non-commercial web app

### Takeaway
PreBot almost certainly does **not** need VERBİS registration (non-sensitive data, under 50 employees and under 100M TL balance sheet). It still must meet KVKK's other duties: a clear **aydınlatma metni** (privacy notice) at sign-up, **data security measures** (art. 12) and **retention/deletion**. Since 1 June 2024, cross-border transfers (Google OAuth, Discord, browser push services, a VPS abroad, Sentry, etc.) fall under the amended **Article 9**. The routes are an adequacy decision (none confirmed found), appropriate safeguards (standard contracts notified to the Authority within 5 business days), or occasional-transfer exceptions. Explicit consent is valid only for non-recurring transfers. Non-essential cookies need opt-in consent under the KVKK cookie guide; strictly necessary auth cookies don't.

### Cited Findings
- **VERBİS:** Board decision 2025/1572 (4 Sep 2025, published in the Resmî Gazete on 1 Oct 2025) keeps the exemption for controllers whose main activity isn't processing special-category data: fewer than 50 employees **and** annual balance sheet under 100 million TL. For controllers whose main activity is special-category data, the thresholds are now under 10 employees and under 10 million TL. Controllers not keeping balance-sheet-based books are judged on employee count only. Implementation principles were announced in Jan 2026. — [hukukihaber](https://www.hukukihaber.net/kisisel-verileri-koruma-kurulunun-04092025-tarihli-ve-20251572-sayili-karari-isiginda-verbis-kayit-yukumlulugunun-istisna-kapsaminda-degisimi); [Erdem & Erdem](https://www.erdem-erdem.av.tr/bilgi-bankasi/verbis-kayit-yukumlulugune-iliskin-yeni-istisnalarin-uygulama-esaslari-aciklandi); [Alomaliye Jan 2026](https://www.alomaliye.com/2026/01/13/kisisel-verileri-koruma-kurulunun-2025-1572-sayili-kararinin-uygulama-esaslari/)
- The VERBİS exemption doesn't lift other duties: the aydınlatma (art. 10) and technical and administrative security measures (art. 12) still apply. — [quasa.io](https://quasa.io/tr/media/verbis-istisnasi-kvkk-yukumluluklerini-ortadan-kaldirmiyor); [hukukihaber](https://www.hukukihaber.net/kisisel-verileri-koruma-kurulunun-04092025-tarihli-ve-20251572-sayili-karari-isiginda-verbis-kayit-yukumlulugunun-istisna-kapsaminda-degisimi)
- Older pages saying controllers processing special-category data must always register are pre-2025 and outdated. — [mihci.av.tr (outdated)](https://mihci.av.tr/verbis-kaydi/)
- **Cross-border (art. 9, post-2024 amendment):** transfer is possible with an adequacy decision; otherwise with appropriate safeguards (BCRs, Board-published standard contracts, written undertakings); otherwise with occasional-transfer exceptions (explicit consent, contract performance, rights, vital interests, public interest). Explicit consent isn't suitable for ongoing or continuous transfers. Using a cloud provider abroad counts as a transfer. Violations can be fined under art. 18. — [Bilal Alyar Hukuk](https://bilalalyar.av.tr/kvkk-uluslararasi-veri-aktarimi/)
- Standard contracts must be notified to the Authority within 5 business days after signing (physically, by KEP, or via the Standart Sözleşme Bildirim Modülü announced 25 Oct 2024). Only optional/alternative clauses may be changed. Both parties' signature dates must appear. Non-notification can lead to a fine. Transfers based on explicit consent under the old regime were accepted until 1 Sep 2024. — [KVKK duyurusu](https://www.kvkk.gov.tr/Icerik/8043/Standart-Sozlesme-Bildirim-Modulu-Hakkinda-Kamuoyu-Duyurusu); [Erdem & Erdem](https://www.erdem-erdem.av.tr/bilgi-bankasi/yurt-disina-kisisel-veri-aktariminda-kullanilacak-standart-sozlesmelerde-dikkat-edilmesi-gereken-hususlara-iliskin-kamuoyu-duyurusu); [Cottgroup](https://cottgroup.com/tr/blog/kvkk-gdpr/item/standart-sozlesme-bildirim-yukumlulugu-ve-yaptirimlari)
- **Cookies:** KVKK's "Çerez Uygulamaları Hakkında Rehber" (first published 2022; the Authority's site shows a "Temmuz 2025" edition, KVKK Yayınları No: 69). Strictly necessary cookies (e.g., first-party session/auth cookies) rely on legal bases other than consent. Non-essential (analytics/marketing) cookies need explicit consent. A cookie wall that makes site access conditional on consent is problematic. Pre-ticked boxes aren't valid consent. Making "Reject all" as visible as "Accept all" is recommended (law-firm interpretation). — [KVKK Çerez Rehberi](https://kvkk.gov.tr/Icerik/7353/Cerez-Uygulamalari-Hakkinda-Rehber); [hukukihaber](https://www.hukukihaber.net/kvk-kurumunun-cerez-uygulamalari-hakkinda-yayinladigi-rehber); [hukukcularevi](https://hukukcularevi.com/cerez-politikasi-ve-cerez-onayi-kvkk/)
- **Commercial messages (Law 6563 / İYS):** devices receiving push notifications are described as electronic communication tools. Commercial electronic messages need prior consent (recordable in İYS); the sender must prove consent; consent can't be solicited via a commercial message. — [Mıhcı Hukuk](https://mihci.av.tr/ticari-elektronik-iletiler/); [Cottgroup İYS](https://cottgroup.com/tr/mevzuat/item/ileti-yonetim-sistemi-ve-yeni-uygulamalar) (secondary)

### Inferences
- **P0 — Aydınlatma metni (Turkish privacy notice)**, linked at the OAuth sign-in button and in the footer. Cover: controller identity (the developer as a real person), data categories (OAuth ID/e-mail/name/avatar, Discord ID, Riot ID, listings, push subscription endpoint, IP/logs), purposes, legal bases (art. 5/2-c contract performance for the service; 5/2-f legitimate interest for security logs), recipients (Google, Discord, push services such as FCM/Mozilla/Apple, VPS host, Sentry if used), cross-border transfer, retention periods, and art. 11 rights with a contact e-mail. Keep it separate from any consent text (the Board expects aydınlatma and açık rıza to be separate).
- **P0 — Push notifications:** PreBot's transactional notifications (your lobby filled, someone joined) are a user-requested service feature, not commercial messages, so the browser permission and an in-app toggle are the practical "consent". Don't send marketing or promotional pushes. If PreBot ever does, 6563/İYS consent rules may apply. (Inference; no source specifically maps web push opt-in to İYS.)
- **P0 — Cookies:** if PreBot uses only the auth cookie, antiforgery cookie and culture cookie, a cookie banner isn't required. A short "Çerez Politikası" listing them suffices. Adding Google Analytics or similar would trigger opt-in consent with an equal-weight "Reddet" button. Prefer no third-party analytics, or self-hosted cookieless analytics.
- **P1 — Cross-border transfers:** the hardest part for a hobby project. Practical risk-reduction steps: (1) choose a VPS located in Turkey if affordable, or document the foreign host; (2) minimize what goes abroad (push payloads with IDs and short text only; Sentry with PII scrubbing, or self-hosted GlitchTip on the same VPS); (3) for big providers (Google, Discord, push services), the user initiates the relationship with those services directly. Whether that qualifies as the controller's "transfer" or an occasional/contract-performance exception is a legal judgment. **Recommend a short consultation with a KVKK lawyer** or at least documenting the analysis. Note that Google/AWS-type providers have published KVKK standard-contract offerings (unverified).
- **P1 — Retention:** define and implement periods (e.g., closed listings 90 days then anonymize; failed push subscriptions 30 days; app logs 30 days; backups 6 months) and an account-deletion flow ("Hesabımı sil") that removes the user, their subscriptions and listings. This satisfies art. 7 deletion and the deletion-policy expectation.
- **P2 — Data breach readiness:** KVKK requires notifying the Board of breaches "en kısa sürede" (interpreted by the Board as 72 hours). Keep a one-page incident runbook. (Unverified here.)

### Gaps
- Didn't retrieve the official text of KVKK art. 9 or the Regulation (Yönetmelik) of 10 July 2024 on cross-border transfers, nor whether any adequacy decision had been issued by Nov 2026.
- No authoritative source found on whether a controller using Google/Discord OAuth or browser push services (FCM, Apple, Mozilla) is treated as making an art. 9 transfer that requires standard contracts. This is legally unsettled for small controllers; needs a lawyer.
- 72-hour breach notification and the separation of aydınlatma and açık rıza come from general knowledge of Board decisions/guides, not re-verified here.
- No source found mapping web push opt-ins to İYS consent.

### Cited Findings
- No sources were fetched for this question within the budget.
